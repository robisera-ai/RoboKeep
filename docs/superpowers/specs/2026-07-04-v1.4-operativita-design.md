# Spec — v1.4 Operatività & integrità

**Stato:** approvato (design) · **Data:** 2026-07-04
**Roadmap:** quarta tappa di [2026-06-24-roadmap-design.md](2026-06-24-roadmap-design.md)

## Problema

Dopo versioning (v1.2) e file aperti (v1.3), restano quattro mancanze operative:

1. **Una sola pianificazione per tutti i job**: chi vuole i documenti ogni sera e le foto la
   domenica non può. Serve la pianificazione **per job**.
2. **I log vivono negli zip su disco**: per rileggere l'esito di ieri bisogna aprire gli archivi
   a mano, e l'app ricorda solo l'**ultimo** esito. Serve una **cronologia** delle esecuzioni con
   un **visualizzatore log in-app**.
3. **Nessuna prova che le copie siano identiche**: robocopy confronta data/dimensione, non il
   contenuto. Per i job critici serve la **verifica integrità** (hash).
4. **Niente limite di banda** per i backup su rete e **nessun export/import** della configurazione.

## Decisioni prese (brainstorming)

- Tutte e quattro le funzioni nella v1.4.
- Frequenze pianificazione: **giornaliera, settimanale, mensile** (niente ripetizioni infra-giornaliere).
- Verifica integrità: **pulsante manuale + casella per job** "verifica dopo ogni backup".
- Pianificazione = **un'attività di Windows per job** (funziona ad app chiusa); niente timer
  interni residenti.
- Cronologia = **file JSON** (`runhistory.json`), tetto 500 voci; niente database.
- Export config: le password restano cifrate DPAPI (su un altro PC vanno reinserite — è una
  garanzia, non un difetto); import con conferma e backup automatico della config attuale.

## Modello dati

**`BackupJob`** — nuove proprietà (tutte con default = comportamento attuale):

| Proprietà | Tipo | Default | Note |
|---|---|---|---|
| `Schedule` | enum `ScheduleKind` (`None`, `Daily`, `Weekly`, `Monthly`) | `None` | |
| `ScheduleTime` | string `"HH:mm"` | `"21:00"` | usata se Schedule ≠ None |
| `ScheduleWeekDay` | `DayOfWeek` | `Monday` | usata se Weekly |
| `ScheduleMonthDay` | int 1–31 | `1` | usata se Monthly; 29–31 → l'attività scatta solo nei mesi che hanno quel giorno (comportamento schtasks) |
| `VerifyAfterRun` | bool | `false` | verifica hash automatica dopo ogni backup riuscito |
| `InterPacketGapMs` | int | `0` | `/IPG:n` se > 0; pensato per backup su rete |

**`RunHistoryEntry`** (nuovo record): `JobName`, `Kind` (`"backup"` \| `"verify"`), `StartedAt`,
`FinishedAt`, `Success`, `ExitCode`, `FilesCopied`, `FilesSkipped`, `FilesExtra`, `FilesFailed`,
`DirsFailed`, `LogPath`. Le verifiche riusano i campi conteggio: `FilesCopied` = verificati,
`FilesFailed` = differenti+mancanti, `FilesSkipped` = saltati (in uso).

## Componenti

| Componente | Responsabilità |
|---|---|
| `Core/Services/RunHistoryStore.cs` | Storico su `runhistory.json` nella cartella dati. `Append(entry)` (best-effort: mai bloccare il run), `List()` / `List(jobName)` in ordine cronologico inverso, tetto 500 voci (le più vecchie escono). File corrotto → riparte vuoto. |
| `Core/Services/SchtasksArgs.cs` (**puro**) | Da job → argomenti `schtasks` per creare/eliminare l'attività per-job: nome `RoboKeep - <nome-sanificato>`, trigger daily/weekly/monthly con orario e giorno, azione `RoboKeep.exe --job "<nome>"`. Sanificazione caratteri non validi nel nome attività. |
| `SchedulerService` (esteso) | `SyncJobTask(job, exePath)`: crea/aggiorna l'attività se `Schedule ≠ None`, la elimina se `None`. `RemoveJobTask(jobName)` per cancellazione/rinomina job. Esecuzione `schtasks` con controllo exit code. La pianificazione globale esistente ("tutti i job") resta invariata. |
| `Core/Services/IntegrityVerifier.cs` | `VerifyAsync(sourceDir, destDir, progress, ct)` → `VerifyResult(Checked, Mismatched, Missing, Skipped, MismatchedPaths[cap 50])`. Cammina la sorgente, per ogni file calcola SHA-256 di entrambi i lati e confronta; file mancante in destinazione → Missing; IOException in lettura (file in uso) → Skipped. Progress ogni 50 file ("verificati n/m"). Gira su thread di background, annullabile. |
| `Core/Services/VerifyTargetResolver.cs` (**puro** + IO minimo) | Destinazione effettiva della verifica: job normale → `Destination`; job versionato → lo snapshot più recente (riusa la logica nomi di `SnapshotService`); nessuno snapshot → esito "niente da verificare" (messaggio, non errore). |
| `Core/Services/LogArchiveReader.cs` | Dal `LogPath` di una voce di cronologia → testo del log, leggendo dentro lo zip archiviato senza estrarlo su disco. Log mancante/zip corrotto → messaggio "log non più disponibile". |
| `Core/Services/ConfigTransfer.cs` | `Export(config, path)`: serializza la config così com'è (password DPAPI incluse). `Import(path)`: valida il JSON → `AppConfig`; il chiamante fa backup `config.backup-<yyyyMMdd-HHmmss>.json` prima di sostituire. |
| `RobocopyArgsBuilder` | `/IPG:n` dopo `/MT` quando `InterPacketGapMs > 0` (in entrambe le passate). |
| `BackupRunner` | Dopo ogni run reale: `historyStore.Append(...)`. Se `VerifyAfterRun && Success && !dryRun`: esegue la verifica subito dopo, righe `[verifica]` nel log, seconda voce di cronologia `Kind="verify"`. |

## UI

- **Toolbar**: pulsante **"Cronologia"** (sempre attivo) e **"Verifica"** (attivo con job
  selezionato, disattivo durante un run). La verifica manuale si comporta come un run: log live
  con avanzamento, pulsante che diventa Annulla (nuovo `RunKind.Verify` in `MainViewModel`),
  esito nel riepilogo e in cronologia.
- **Finestra Cronologia** (`HistoryWindow`): griglia (data/ora, job, tipo, esito, conteggi,
  durata) con filtro per job (combo "Tutti i job" + nomi); doppio clic → **visualizzatore log**
  (`LogViewerWindow`): testo monospace in sola lettura, titolo = job + data.
- **Editor job**: sezione **"Pianificazione"** (combo frequenza; campo orario HH:mm; combo giorno
  della settimana o campo giorno del mese, visibili secondo la frequenza); casella **"Verifica
  l'integrità dopo ogni backup"** con hint sul costo; campo **"Rallenta la copia (ms tra i
  pacchetti)"** con hint in linguaggio semplice (per backup su rete; 0 = piena velocità).
- **Al salvataggio del job**: `SyncJobTask`. Alla **rinomina**: rimozione attività col vecchio
  nome + creazione col nuovo. Alla **cancellazione** del job: rimozione attività.
- **Impostazioni**: pulsanti **"Esporta configurazione..."** / **"Importa configurazione..."**
  (dialoghi file standard). Import: conferma esplicita ("sostituirà tutti i job e le
  impostazioni; le password importate da un altro PC andranno reinserite"), backup automatico,
  ricarica completa della UI.
- **Localizzazione**: tutte le stringhe nuove in 5 lingue (`Loc.cs` UI, `CoreLoc.cs` log/riepiloghi).

## Robustezza

- **Storico**: `Append` in try/catch — un problema di scrittura non deve mai far fallire un backup.
- **Attività Windows**: nomi sanificati; `schtasks` fallito → messaggio chiaro nell'editor, il
  salvataggio del job riesce comunque (la pianificazione si può ritentare).
- **Verifica**: mai due run contemporanei (riusa il gate esistente `_running`); file in uso →
  Skipped, non Mismatched; VSS **non** viene usato dalla verifica (v1: semplice; i saltati sono
  dichiarati nel riepilogo).
- **Import**: validazione prima di toccare qualsiasi cosa; backup prima della sostituzione;
  attività pianificate risincronizzate per tutti i job dopo l'import.

## Test

Unit (xUnit):
- `RunHistoryStore`: append/list, filtro per job, tetto 500, file corrotto → vuoto, ordine inverso.
- `SchtasksArgs`: daily/weekly/monthly con orario e giorno; sanificazione nomi; argomenti delete.
- `IntegrityVerifier` (cartelle temp): identici → 0 differenti; un byte cambiato → 1 differente;
  file mancante in dest → 1 Missing; annullamento a metà; file bloccato → Skipped.
- `VerifyTargetResolver`: job normale → Destination; versionato con snapshot → l'ultimo; senza → null.
- `LogArchiveReader`: round-trip testo da zip; zip mancante → messaggio.
- `ConfigTransfer`: export→import round-trip; JSON invalido → errore pulito.
- `RobocopyArgsBuilder`: `/IPG` presente/assente.
- `BackupJob`: default nuove proprietà + round-trip JSON.

Smoke manuale:
1. Job con pianificazione settimanale → attività visibile nell'Utilità di pianificazione con
   orario giusto; rinomina job → attività rinominata; cancellazione → attività sparita.
2. Verifica manuale su un backup sano → 0 differenti; corrompi un file in destinazione a mano →
   la verifica lo trova.
3. Cronologia: esecuzioni e verifiche elencate, doppio clic apre il log giusto.
4. Export config, modifica un job, import → tutto tornato com'era, backup creato.
5. `/IPG`: anteprima comando mostra il flag; run più lento con valore alto.

## Fuori scope (YAGNI)

- Ripetizioni infra-giornaliere ("ogni N ore") — si aggiungono se richieste.
- Ricerca/filtri avanzati nel visualizzatore log.
- Riparazione automatica dei file differenti trovati dalla verifica (si rilancia il backup).
- Export selettivo (solo alcuni job).
